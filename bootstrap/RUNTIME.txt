Runtime support for self-hosting

The compiler port uses ordinary language operations. No primitive invokes,
embeds or delegates to a compiler. Primitive ids 0 through 45 are unchanged;
ids 46 through 65 add the following general-purpose operations to both the
checked interpreter and native runtime.

46 stringLength : String -> Int
47 stringCodeAt : String -> Int -> Int
48 stringSlice : String -> Int -> Int -> String
49 stringFromCode : Int -> String
50 compareString : String -> String -> Int

Strings contain Unicode scalar values and may contain NUL. Length and indices
count scalars, not UTF-8 bytes. Indexing is zero based. Slices take start/count
and permit an empty slice at the end. Negative/out-of-range indices, counts,
surrogates and code points above U+10FFFF fail. Comparison is lexicographic by
scalar value, returning -1, 0 or 1. Native strings build and cache scalar byte
offsets on first indexing; those offsets follow the lifetime of their string.

51 readDouble : String -> Double
52 doubleToBits : Double -> Int
53 doubleFromBits : Int -> Double

readDouble accepts an optional sign, ASCII digits, an optional decimal point
followed by digits, and an optional e/E exponent with optional sign and digits.
It consumes the entire string. Whitespace, NaN/Infinity spellings, hexadecimal
numbers and missing digits are rejected. Decimal overflow/underflow yield IEEE
infinity/zero. The bit conversion operations preserve all 64 bits, including
signed zero and NaN payloads. Int holds the unsigned pattern (0..2^64-1).

54 seq : forall a b. a -> b -> b
55 panic : forall a. String -> a

seq returns its second argument only if its first argument reaches weak head
normal form. Fields of a constructor and bodies of closures remain lazy.
panic reports a runtime failure only when demanded. When multiple demanded
pure operands fail, their evaluation order is unspecified: strict-worker
optimization may expose different diagnostics across backends. seq does not
order those pure failures. IO effects retain their order, and unused arguments,
branches and results remain lazy; the shared backend tests check these rules.

56 readFile : String -> IO String
57 writeFile : String -> String -> IO Unit
58 fileExists : String -> IO Bool
59 canonicalPath : String -> IO String
60 getArgCount : IO Int
61 getArg : Int -> IO String
62 putErr : String -> IO Unit
63 exitWith : forall a. Int -> IO a
64 getExecutablePath : IO String
65 getContents : IO String

File operations use strict UTF-8 and preserve NUL in contents. A path containing
NUL is rejected. writeFile creates or truncates a file. fileExists tests regular
files, following symlinks; directories and missing files return false.
canonicalPath requires an existing path and resolves it to an absolute path
with symlinks removed. getArg uses a checked zero-based index, excluding the
executable name. Native main supplies argc/argv through mlf_set_args; manually
linked entries default to no arguments. The native CLI accepts program
arguments after -- for --run and --run-xmlf. putErr writes and flushes standard
error without adding a newline. exitWith accepts status 0..255 and terminates
without running pending actions. getExecutablePath returns the canonical
absolute executable location on macOS and Linux. getContents reads all remaining
standard input, retaining line endings and NUL and rejecting invalid UTF-8.

The MLF runtime provides runTermWithArguments and runProgramWithArguments
for interpreter callers.

Validation lives in tests/Tests/BootstrapPrimitives.emlf and the shared Backends matrix.
Every runtime row executes both implementations, including Unicode and NUL,
bit patterns, strict input errors, escaped primitive values, laziness, files,
arguments, stderr ordering, exit codes and retained strings across collection.

66 stReturn : forall s a. a -> ST s a
67 stBind : forall s a b. ST s a -> (a -> ST s b) -> ST s b
68 runST : forall a. (forall s. ST s a) -> a
69 newSTArray : forall s a. Int -> a -> ST s (STArray s a)
70 readSTArray : forall s a. STArray s a -> Int -> ST s a
71 writeSTArray : forall s a. STArray s a -> Int -> a -> ST s Unit
72 lengthSTArray : forall s a. STArray s a -> ST s Int

ST and STArray are opaque constructors of kind * -> * -> *. The inner state
quantifier in runST prevents usable region-specific arrays or actions from
escaping. The prelude supplies Monad (ST s); explicitly forall-s-signed actions
support do notation. IO and ST cannot be converted or executed by one another.

Creating an action does not execute it. Array sizes and indices are checked
when their operations execute. Initial and stored values remain lazy and shared;
reads snapshot the current value before later writes. Repeated actions repeat
effects, nested runST calls have independent local continuation stacks, and a
shared pure runST expression follows ordinary call-by-need memoization. Its
saturated primitive returns canonical WHNF while preserving lazy result fields.

The native runtime has separate ST action/array tags, boxed GC-visible cells,
and a local continuation loop. It never explicitly collects inside unrooted
pure frames; BDWGC traces such frames automatically. Both reference interpreters
use independent persistent stores with lazy cells and no unsafe host IO.
StateCases/StateTypes/StateRuntime and bootstrap/tests/StateRuntime check region
typing, independent target checking, semantics and both backends. runtime_st.c
also checks the public ABI and retained roots under compact BDWGC allocation.

Native allocator and ABI

All native executables use the compact Boehm-Demers-Weiser collector layout.
The collector scans native stacks and reclaims unreachable values during pure
evaluation. Small integers, booleans and nullary constructors are immediate
values. Heap values have no custom collector object header; unary/binary
constructors store inline fields and wider constructors use a contiguous tail.

Install BDWGC locally and set MLF_GC_PREFIX, or supply bdw-gc.pc through
PKG_CONFIG_PATH. All package builds select its include flags and libraries;
the package manager does not download dependencies. Manual builds compile
mlf_runtime.c with BDWGC/GMP include flags and link BDWGC, GMP and libm.
MLF_USE_BDWGC and MLF_COMPACT_BDWGC are no longer mode switches. Do not install
GMP memory hooks before runtime initialization.

Every pointer-bearing allocation, including closure environments, evaluation
stacks, arrays and hash tables, belongs to the collector. GMP limbs use atomic
collector allocations. Memoized thunks and popped continuation slots clear
obsolete references. Native stack support preserves suspended evaluations and
recursive binding holes. GC_DEBUG and MLF_ALLOCATION_AUDIT remain supported.

All LLVM command spellings emit compact-GC; -gc spellings are aliases. Old
standard-layout LLVM and objects fail to link against this runtime's ABI guard
and must be regenerated. There is no standard allocator/collector fallback.
The shared backend matrix compares interpreter and compact native execution;
port executes 25 checked compiler probes through LLVM. Stress coverage retains
suspended applications, cyclic data, GMP integers, arrays and tables across
long pure allocation intervals and checks results with independent references.

82 processSupervisor : String -> IO String

This private monomorphic transport calls the dynamic subprocess supervisor in
this process. It is not runProcess, a shell, or a task-value lookup. The public
API is the separate mlf-async library's Async.Process module. Primitive numbers
0..81 remain unchanged. New compiler entries require the additional compact
runtime symbol mlf_require_process_supervisor_v1_abi; released-seed entries keep
the old compact guard and can link to the new runtime. There is no fallback
that silently runs a whole static runner for one dynamic operation.

Request fields are NUL-terminated UTF-8 strings, headed by MLF-PROCESS-1 and an
operation. The complete request is limited to 1 MiB and 4096 fields. Replies
contain a decimal status followed by bounded metadata, at most 512 bytes; zero
means success. Nonzero statuses are the mlf_process_status enum and a stable
status name. No process stdout/stderr is returned or accumulated in memory.

Operation fields after the version and operation:
  version: no fields; success returns 1.
  clock: no fields; returns monotonic milliseconds (metadata only).
  pause: milliseconds, 0..1000; bounded host sleep for the interpreter timer driver.
  create: jobs, max_pending, max_retained; returns opaque decimal scope ID.
  submit: scope, executable, cwd, stdin, stdout, stderr, env_mode,
          running_ms, total_ms, argc, argv[argc], envc, NAME=VALUE[envc].
          argv includes argv[0]. env_mode 0 inherits at launch, 1 replaces.
          Returns scope, generation, slot, never a native pointer.
  poll: scope; returns event or would_block/empty/wait_timeout.
  wait: scope, wait_ms; returns one event; -1 waits indefinitely.
  await: scope, handle_scope, generation, slot, wait_ms; returns an outcome.
  cancel: scope, handle_scope, generation, slot, nonnegative_reason.
  request-cancel: same fields as cancel, accepts without joining; subsequent
                  supervisor calls service cleanup until the outcome is terminal.
  cancelScope: scope, nonnegative_reason.
  close: scope, mode (0 join, 1 cancel-and-join); releases retained outcomes.

An outcome is kind, exit_code, launch_error, cleanup_error, cancel_reason.
Kinds are exited=0, launch_failed=1, cancelled=2, timed_out=3. An event prefixes
these fields with scope, generation, slot. Nonzero process exit is outcome data.
Repeated await does not consume an event or restart work. Scope IDs and handle
generations are validated on every operation; identities are not reused.
Timeout durations are integer milliseconds, limited to UINT32_MAX; zero disables
child timeouts. Total time includes queuing. A wait timeout does not cancel work.
Only supervisor calls service deadlines/admission; non-yielding MLF work can
delay both. File output avoids pipe-buffer deadlocks, but disk use is not capped.

The interpreter host bridge uses checkpoint and finish requests: checkpoint
returns a private serial mark; finish takes mark and join/cancel mode and closes
only scopes created after that mark. This preserves outer native/interpreted
scopes during nested evaluation. Native panic, exitWith, and orderly runtime
termination cancel-and-join all remaining scopes. The raw shutdown request does
the same. POSIX guardian/Windows Job Object guarantees and containment limits
are documented with the supervisor; runtime cleanup cannot intercept SIGKILL.
The transport retains integer-only scope metadata. It stores no typed MLF
outcomes, suspended MLF closures, or callbacks in untraced native memory.

Bootstrap transition: scripts/bootstrap-async.sh uses the released seed to
compile stage 1 in an isolated snapshot with the bootstrap/seed-compat host
bridge and a seed-schema manifest.
That host bridge explicitly returns unsupported for process interpretation.
The released compiler also builds a matching package manager before stage 2:
the released manager's independent interface decoder rejects newly appended
primitives in the stage-1 prelude. Dependency-closure validation stays enabled.
Stage 1 can compile primitive-82-bearing code, and rebuilds stage 2 using the
separate native-source snapshot. Stage 2 is required for checked-interpreter/native async parity.
The existing source-smoke import closure and package-manager sources do not
import the new primitive-bearing host or Async.Process modules.

83 asyncScopeNew : Int -> Int -> IO AsyncScope
84 asyncScopeClose : AsyncScope -> IO Unit
85 asyncNewCompletion : forall a b. AsyncScope -> (Completion a -> IO b) -> IO b -> IO b
86 asyncResolveCompletion : forall a. Completion a -> a -> IO Int
87 asyncReadCompletion : forall a b. Completion a -> (a -> IO b) -> IO b -> IO b
88 asyncSubscribeCompletion : forall a. Completion a -> (a -> IO Unit) -> IO AsyncSubscription
89 asyncSubscriptionStatus : AsyncSubscription -> IO Int
90 asyncCancelSubscription : AsyncSubscription -> IO Int
91 asyncStep : AsyncScope -> IO Int
92 asyncEnqueue : AsyncScope -> IO Unit -> IO AsyncSubscription
93 asyncDelay : AsyncScope -> Int -> IO Unit -> IO AsyncSubscription
94 asyncWait : AsyncScope -> Int -> IO Int

AsyncScope, Completion a and AsyncSubscription are opaque primitive types.
Allocation quantifiers are outside the IO action; executing one cold allocator
again creates a fresh cell. An allocated cell fixes one payload type, which may
itself be polymorphic. No integer-to-typed-handle or consumer-to-producer cast
exists. Library Fiber constructors must hide their underlying completion.

Scope creation bounds retained cells and outstanding subscriptions separately.
Pending waiters, ready callbacks and timers reserve callback capacity before
resolution. Resolution commits once and never executes callbacks. Read returns
the retained lazy value, or executes the supplied fallback while pending/closed.
Failed allocation runs its fallback; rejected subscriptions retain a status and
no callback. Closing a scope clears all result and callback/timer roots.

Statuses: 0 OK, 1 EMPTY, 2 ALREADY_RESOLVED, 3 CLOSED, 4 FULL, 5 WRONG_OWNER,
6 CONSUMED, 7 NO_MEMORY (fatal in public allocation), 8 BUSY. Each step dispatches
at most one callback through the normal IO loop, without recursively entering
mlf_run. Same-scope recursive step/wait returns BUSY without changing the queue.
Stepping a different scope is allowed. Already running callbacks are cooperative.

Delay registers a cancellable IO action for a monotonic millisecond deadline;
0..4294967295 milliseconds are accepted. Registration never sleeps or invokes
user IO. Step/wait mature due timers after existing ready work; equal deadlines
retain registration order. Wait runs no callbacks and returns 0 when work is
ready, 1 when no ready/timers remain or its bounded timeout expires, 3 if closed,
or 8 while already dispatching. A wait limit of -1 waits for the earliest timer;
0 is a poll, and other limits are 1..4294967295 milliseconds. Host sleeps are
bounded to 1000 milliseconds and never exceed the nearest timer/timeout.
Timer precision is milliseconds; execution may be delayed by non-yielding IO.

The checked interpreter threads a persistent IO store through every IO bind.
Closed scopes are removed rather than retained as tombstones; unforgeable,
monotonic issued identities distinguish stale handles without a historical map.
Only clock/pause metadata crosses the bootstrap host bridge. Results and resume
closures stay in the traced typed store. Native objects are scanned BDWGC roots.
New codegen entries require mlf_require_async_completion_v2_abi, and the cache
key includes completion-v2; old native object IDs are not silently reused.
