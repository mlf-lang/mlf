# Stage15: call-local directory reuse during authentication

This is a narrow runtime optimization of the opt-in IR8 route. It changes only
`runtime_v8/rir8_binding.c` in production. Packet ABI, allocator, object layout,
source language, default placement/fault policy and the maintained v7 route are
unchanged. The existing 67,108,864 work limit is not raised.

## What is reused, and what remains checked

`domain_auth` finds a registered pointer by visiting rows in order. Previously,
every visited row revalidated the same object directory entry. The first visit
still performs that complete validation, storing its result in a local stack
object. Later visits within that one call reuse only this directory entry.

This relies on the existing borrowed immutable-root and disjoint-output contract.
No callback or root mutation occurs during the scan. No cache survives the call,
and independent public reads/refs still validate the directory afresh. Null
references and empty domains do not gain an eager directory read.

All other checks remain: both span lookups, layouts, domain/kind/owner/count
predicates, checked arithmetic, per-row extents/alignment/copies and every
preceding table-row ID. Authentication still uses pointer equality against each
validated row, never arithmetic on an unregistered pointer. A matched early row
does not cause later rows to be inspected.

The first loop iteration is peeled rather than adding a new uncharged cache
branch. Exactly one directory examination is removed for each later visit
reaching that examination. The failing ID row counts as a visit too. The current
ABI charges 185 units per such examination; the tests derive this from the fixed
predicate/copy formula and `sizeof`, not from timing. Remaining work is charged
normally. Exhaustion coordinates at the same numeric budget can legitimately
move; every budget below the new success cost must still fail with unchanged
output and consistent counters.

Binding admission does not call these pointer-authentication paths. Its complete
report, including work counters, stays exact. Only the two dynamic fields
`guard_work_used` and `guard_work_total` are permitted to decrease in full-program
comparisons. This differs from Stage12, which also reduced admission work.

## Correctness results

The existing bounded-reader C driver now covers 4,033 cases per build across all
20 table and six descriptor domains. O0/O2 each pass:

- an exact Stage14 differential, removing 193,140 charged units across the shown
  cases while preserving every non-work field;
- an exact Stage11 differential, removing 535,760 units from the combined Stage12
  and Stage15 changes, with the earlier optimization explicitly accounted for;
- portable current-only expectations, sentinels and all below-success budgets.

Controls include independent-call directory mutation/restoration, one/two-row
spans, misses, null/empty scans before malformed directories, corrupted preceding
and target IDs, ignored post-match corruption, and first/middle/final auth budgets.
Both optimization levels produce exact matching reader reports within each lane.

The existing native runtime suite passes all 22 tests at both O0/O2, including
100-entry stress and the expected fault/destruction case. All 22 paired native
reports match between optimization levels.

Ten retained genuine source-program conditions were freshly checked/emitted and
compiled/run at O2. They cover older nominal SUM and lazy-tail programs plus
closed recursion and recursive scalar/shared-view captures. Generated bytes are
exact; the full native reports differ only in the two lower dynamic work fields.
Both recursive-capture modes also pass ASan/UBSan with reports exactly equal to
ordinary execution; LeakSanitizer is off. The original fixed fuel19 fault pair
still retains or explicitly retires the same 4,848 bytes, with the same fault and
complete destruction report. No fuel threshold search or GHC rerun is involved.

For the small Stage14 recursive-capture program, dynamic work drops from
65,540,230 to 53,669,890 coarse and from 64,949,552 to 53,056,827 with groups. All
other trace, return, allocation, RC and ledger fields remain exact. This provides
more room below the unchanged cap, not a claim of deep recursion qualification.

## Finite same-program timing

An isolated local cohort reused the existing benchmark process transport,
quiet fresh-entry driver and predeclared statistics. The three Stage09 coarse
programs, generated C, shared objects, compiler/flags and driver were identical
between lanes; only the binding translation unit differed. The baseline is the
Stage14 runtime, whose trace exactly matches the actual Stage12 optimized result.

Compilation was excluded. Each measured process included startup, one admission,
100 fresh entries and final JSON serialization. Quiet mode retained guards and
counters. After 18 qualification checks and six fixed warmups, all 42 alternating
samples were kept: seven pairs per program. No concurrent local compiler/heavy
test or profiler ran during this cohort.

- Shared callable field: median paired optimized/baseline wall ratio 0.8317,
  about 16.8% less time in this cohort. Batch medians were 1.2017 s and 1.0032 s.
- Curried callable field: ratio 0.8124, about 18.8% less time. Batch medians were
  2.0139 s and 1.6503 s.
- Scalar field: inconclusive. Batches were below the predeclared 250 ms floor;
  the difference was not sufficiently separated from paired variability.

Allocation counts, requested-byte peaks and RC work were unchanged. These are
finite uninstrumented observations, not population guarantees, RSS reductions,
an original-GC comparison or a Perceus result. They do not establish complete GC
replacement. Earlier Stage12 timing remains a separate historical cohort.

## Reproduce portable checks

Use new external output directories:

```sh
T=tools/experimental/resource-native/tests
python3 -B "$T/test_binding_readers.py" --cc cc --output /tmp/ir8-readers-new
python3 -B "$T/test_stage05_runtime_native.py" --cc cc --stress \
  --optimization O0 --output /tmp/ir8-native-o0-new
python3 -B "$T/test_stage05_runtime_native.py" --cc cc --stress \
  --optimization O2 --output /tmp/ir8-native-o2-new
```

Optional `--baseline-root` on the reader test accepts the exact Stage11 or Stage14
source revision and verifies matching headers/packet code before differential
compilation. The existing CI reader step already runs the updated current-only
suite, and the native jobs already run both stress configurations. No workflow
or source-job time-limit expansion is required. Local results do not substitute
for CI on the eventual published head.
