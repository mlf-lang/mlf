# Stage23: closed arrow shared type arguments

**Finite local qualification complete:** all four genuine source cases pass
the native matrix, source/metadata/event observers, sanitizers and fresh default
four-case suite below. Focused arrow guards and a fixed C fault pair also pass.
Exact-commit CI remains pending. No performance or general GC-replacement claim
follows from these checks.

## Admission boundary

The opt-in source route extends complete shared rank-1 type vectors to finite
closed arrows. Every arrow must have the existing Repeat protocol and unknown
result identity. Leaves must be Int, Bool or an exact already-admitted,
parameter-free DATA/SUM atom. This applies recursively at every arrow node,
including unused coordinates. A closed tag or matching physical layout alone
does not establish eligibility. Nominal leaves remain atoms: recursive SUM
fields are not unfolded while checking a type argument.

Open/rigid or higher-rank coordinates, Once arrows, argument-identity arrows,
foreign nominal identities, parameterized families and partial/bare Scheme uses
remain rejected. Generic principal bodies retain their existing scalar/rigid/
Repeat-arrow restrictions; nominal generic operations are not introduced. DATA
field and SUM-case restrictions do not change. Neither do v7, export/2, the
default compiler route, runtime ABI, allocator, placement or fault defaults.

Host checking retains canonical child-before-parent Type IDs, every complete
ordered coordinate, exact E0 resolutions and the full callable contract.
Packet admission and `rt8_instantiate` use a bounded arrow-only traversal to join
Type, canonical-arrow ShapeBinding, unscoped ShapeTyping, CallableContract,
Representation, ShapeSpec and both child representations. Scalar and exact
nominal terminals use their existing checks. All argument checks and work
reservations precede Access publication. Existing scalar/nominal argument paths
keep their prior work accounting; there is no persistent validation cache.

The returned value keeps its actual owner, origin and Access. Returning an
existing INSTANCE through the same or another Scheme does not create a new
INSTANCE, replace its capsule or relabel its original environment. Pending
annotation/parameter applications, shared neutral memos, Down support and
captured owners remain in the ordinary graph; no identity shortcut, cloning,
eager forcing or direct-C replacement is added.

## Source normalization

The shared diagnostic producer and independent replay add closed-arrow direct
type beta. An actual arrow beta selects `shared-rank1-callable/3`; ordinary uses
with arrow coordinates alone do not. Traversal remains outer-first, and `/3`
does not downgrade after subsequent nominal or scalar steps. Full-prefix
substitution, actual witnesses, binder identities, root-type equality, ordinary
erasure and unchanged declarations are still checked.

The capture remains `mlf-shared-source-capture/1`, diagnostic evidence rather
than arbitrary JSON admission or a final export/3 format. Fresh source/build
custody and independent proof replay remain required. Baseline refusals are
preserved: A/B/D reached USE; C reached DIRECT because its old producer retained
an immediate arrow beta. A new C producer invocation supplies the matching `/3`
certificate. Its old `/1` capture is not silently reinterpreted as that evidence.

## Four unannotated source cases

The fixtures in `tests/test_source_v8_arrow_arguments.py` use actual imported
`sharedId : forall a. a -> a` and/or
`sharedApply : forall a b. (a -> b) -> a -> b`. Their local helper and use-site
terms are unannotated. Let `F` below mean `Int -> Int`.

- **A, `shared-id-arrow`:** `sharedId helper` returns the original ordinary
  capturing helper. Uses `[F]` and `[Bool]` share one generic RHS. The returned
  application is reused twice; the original helper runs twice and its pending
  `addInt 20 1` bonus once. The returned helper remains concrete, not INSTANCE.
- **B, `shared-apply-arrow`:** a consumer calls its callable argument twice.
  Complete vectors `[Int, Bool]` and `[F, Int]` join their distinct child
  contracts/environments. The consumer receives the actual pending helper
  wrapper; it is not replaced by a direct closure reference. Bonus runs once.
- **C, `shared-apply-instance`:** an initial call demands
  `inner = sharedApply helper`. A higher-order use of the same Scheme returns
  this original child through an ordinary identity lambda. Vectors are
  `[Int, Int]` and `[F, F]`. The later two calls use the original INSTANCE node,
  Code, capture and environment, not the intervening higher-order child.
- **D, `shared-id-instance`:** the same previously demanded `inner` passes
  through the distinct `sharedId` Scheme. Its original INSTANCE is returned
  with its original environment/capture; the two Schemes retain distinct
  capsules. The helper runs three times including the initial demand, bonus once.

A/B/D have exact `/1` normalization with two Int steps. Fresh C has `/3` and
four ordered steps: outer arrow beta, nested arrow beta, then two Int steps.
All source selectors are derived from actual binders, paths and complete type
vectors, then joined to Code/Site/Env records and the retained native events.
Public events do not expose every owner's Access or capsule; they are not an
exhaustive per-owner proof. These four sources do not test dead coordinates or
nominal arrow leaves, which have separate synthetic controls below.

## Completed first results and focused controls

Each first coarse/O0 run returned Int42/fault0 with all seven live ledger
categories zero, no omitted events and guard mask 117440511. The graphs contain
no Hole/Fill, so this does not claim Fill guard 24 or exhaustive guard coverage.

- A: work 12,929,133; allocated/freed 23,328 bytes; peak 10,264 bytes.
- B: work 29,512,855; allocated/freed 35,936 bytes; peak 13,792 bytes.
- C: work 34,603,892; allocated/freed 43,192 bytes; peak 15,264 bytes.
- D: work 30,262,952; allocated/freed 39,904 bytes; peak 14,592 bytes.

These are tracked ledger/work counts, not RSS or a timing comparison. Host-only
rechecks of those retained reports reject 86 copied-report and 34 structural
controls in total: A 24/7, B 18/9, C 23/9 and D 21/9. Structural mutations test
source/plan/metadata correspondence, not extra native executions.

The genuine A generated pair passes 43 controls per optimizer: 35 copied-packet
rejections and eight real-entry cases. A separate host-checked synthetic raw IR
pair passes 107 per optimizer: 99 copied-packet and eight real-entry cases.
Both pairs have complete O0/O2 report equality. The synthetic pair uses
`forall a b. a -> a` with `[Nested, Int]` and `[Bool, Nested]`, where
`Nested = (Box -> Int) -> (Chain -> Int)`. It therefore covers nested DATA and
self-SUM leaves plus an unused arrow coordinate, without claiming genuine
source coverage for those combinations.

Real-entry controls retain the genuine callbacks. Each intercepted instantiation
delegates exactly once to the real helper; a run may contain several such calls.
They cover foreign Use/Access, capsule and work-boundary failures,
unchanged Access on rejected instantiation, poisoned-session retention and
separate terminal surrender. The seven expected faults retain 4,080 bytes in
the A pair and 3,016 bytes in the nested pair; explicit terminal destruction
retires exactly those amounts in every case. The nested healthy result uses
2,037,821 work units and leaves all seven live ledgers empty.
Copied-packet mutations can reject at earlier
validation guards; each is not claimed to reach only the new arrow predicate.
Known-valid references are a precondition, not arbitrary-pointer/race coverage.

## Bounds and reproduction

No caps are raised. Logical types remain bounded by 4,096 canonical nodes and
depth 32, including substituted results/intermediates; vectors have at most
eight coordinates. There are at most 16 Schemes and 1,024 IR uses/environments;
source replay has the tighter 256-use bound and its existing 2,000,000-work,
10,000-cell/correspondence, depth-100 and 32-MiB raw-value limits. Source nominal
selection remains at most 32 declarations. Existing field/capture/Force/activation
limits remain unchanged. Runtime guard work stays capped at 67,108,864. The
source CLI still defaults to fuel 1,000,000 and retain-on-fault; explicit
terminal surrender reports retirement separately without changing the fault.
