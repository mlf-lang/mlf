# Graph.unify write/provenance audit (source-only)

## Decision and scope
Baseline fc300bc9fdc389b585cbef0630fc8915d53e89c5; pinned Graph SHA 9df4833f55f0826181f8e1e974dc0672753e9462de0d134f64fc3f8c6f6e8a7f. This is a source audit of ALL graph-construction exits inside Graph.unify's first-order/canonicalize/rebind transaction, not all graph-producing APIs in the compiler. No Haskell, compiler, metadata command, shadow or reuse executed. The reader preserves line-numbered source evidence and exact hashes.

There is a bounded, explicit provenance interface to design, but NO complete write certificate exists today. Logging only changed Node pointers or only equations is unsound. A conservative transaction log must account for loser membership removal, alias resolution dependencies, all surviving canonical child projections, and final binder/flag publication. Its retained payloads and demand cost remain unresolved. This report authorizes no implementation or performance experiment.

Vocabulary:
- logical write: field/map assignment in the returned graph construction; it may execute only when its lazy result is demanded.
- may-write: must conservatively invalidate without comparing potentially partial payloads, even if the value happens to be equal.
- rebuild-preserved: reconstructs physical representation while retaining stated logical fields.
No eager deep equality, hashing or printing is permitted to turn a may-write into a clean field.

## Strictness and identity facts

Graph.hs 32–106 defines the meaningful boundaries. forceTag demands both Arr/App children and the Gen child, but not GCon argument-list contents or embedded Kind/name. mkNode/strictNode demand the tag according to forceTag, the Maybe binder constructor, and Flag constructor; they do not force Just binder payload or nested Kind/name. mkGraph demands node/alias map outer trees and nextId, not all map payloads. mapNodeTree recursively forces mapped tree roots/strictNode while retaining physical branch count/prefix and left/right order. Generic IntMap is value-lazy; 'same map key' is not same Node value.

For valid canonical input under this unify:
- no fresh allocation occurs; nextId is carried, not incremented;
- every successful distinct union removes one live representative and records a loser link; smaller signed ID wins;
- old IDs remain meaningful through resolve but are not all live keys;
- output fields on a live key can change without that key being an equation endpoint (canonical children, placement binder, class flag);
- root Gen cannot be merged because tagEquations rejects Gen before bottom cases. This conditional fact does not certify all final binders/root checks.
Raw forged nodes/links, partial lists, invalid nextId and public direct firstOrder/rebind calls are outside those derived premises; the original functions retain their behavior. A complete raw-map certificate would additionally require routing/count/shape/order dependencies, not just logical member equality.

The source comment about arbitrary-precision identities near DenseRebinding is not adopted as an ABI claim: the current selected GHC Primitive representation is fixed independently. This audit does not change signed identity rules or arithmetic.

## What a future complete log would need (not implemented)

Transaction-local graph versions B=input, S=post-firstOrder, C=canonical skeleton, U=sparse-only raised view, F=final. Keep source identity and output representative distinct. Require ordered transfer records for every recursive merge plus alias insertions/deletions; explicit membership epoch; field-provenance records for C's tag-child projection; F parent/flag assignments; and U isolated from F. Mark canonical child fields conservatively dirty on relevant alias changes unless a separately justified dependency walk proves otherwise.

Do not deep-compare names, kinds, child lists or Node records to decide clean. Do not add eager list traversal to generate a complete log. GCon's deferred resolution presents a concrete remaining difficulty: recording the transformation is cheap, but establishing precise per-element unchangedness without forcing the list is not. Marking the whole projection may-write is safe/conservative but can invalidate almost all affected kind/edge facts.

Membership/root/Euler/global-binding facts must invalidate on any relevant may-write, not only a changed scalar interval. Alias terminal absence is a dependency. Physical map reconstruction, iteration order and root checks are not justified by node-pointer reuse. The present read observer's selector tokens are not enough to discharge these write, context and version obligations.

## Falsifiable cases for a later, separately admitted finite gate

1. Ordered (high,low) equation: numeric winner is low but temporary binder/flag source is high (a). Swapping equation orientation may change intermediate demand even if later class reconciliation yields equivalent final fields. A winner-origin-only logger must be rejected.
2. Bottom-to-structure merge redirects a loser used inside an unrelated surviving Arr or GCon. Canonical children there change; GCon tail poison must not be eagerly forced by logging.
3. Multi-merge alias chain: an existing alias entry is byte-unchanged but resolve result changes after its target loses. Terminal absence changing to link-present must invalidate old resolve facts.
4. Rigid/flexible members merge: final class flag may differ from skeleton's a-derived flag; instantiate/raise/weaken/merge error priority must remain exact. A field log cannot bypass these checks.
5. Empty equations: canonicalize/rebind may reconstruct maps/Nodes despite no unions. Such reconstruction is not itself a semantic changed-field count; pointer differences cannot be equated to required invalidation.
6. Same logical membership but malformed Patricia count/prefix/order: no generic preservation theorem from validateGraph. Keep raw helpers/old oracle; do not treat asc-list builder as a canonicality proof.
7. Earlier permission failure plus later deferred child/kind poison: logging pending F fields or intermediate U eagerly must not expose the later poison first.
8. Dense same-parent/different-flag and different-parent/poison-flag cases: test original equality short circuit before claiming reuse of denseFinalNode result.

These are proposed counterexample schemas, not constructed/compiled/passed fixtures. No new run, real shadow, optimization or native work is admitted. The next decision requires an independently reviewable transformation/provenance interface preserving these exact lazy boundaries, not a claim that 92.9% connected nodes are removable.
