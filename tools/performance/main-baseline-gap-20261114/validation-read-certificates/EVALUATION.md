Its 17 checks include unchanged replay, a balanced single-leaf kind error, child-kind change, absent-link insertion, alias cycle, Gen control change, node deletion, root-set change, earlier-error/poison priority, failed-fact repair, dependency replacement, all-fields invalidation, three omitted-dependency mutants and structural-cycle repair.

## Required before any real shadow

The immediate proposed next step is only a Haskell full-field/per-edge dependency observer source design and finite exact gate. It needs its own source review; this Python result does not admit a real shadow producer. It must retain full input validation and the complete original final validator, preserve Graph results and physical map/link representation, and compare ordered errors and controlled poison demand. The original Either-WHNF endpoint must not silently become full result-Graph normalization.

At minimum, dependencies and invalidation must cover existing/absent nodes, root and member changes, alias redirection, tag/kind/flag changes, binder/child redirection, control branches, subfacts and cycles. The current model does not discharge Graph-specific edge/dominance/Euler obligations. A dependency or delta algorithm that first forces all fields may change the accepted partial domain even if it returns the same result on total graphs.

Call identity must be explicit and transaction-local. Existing numeric digest transcripts do not contain the complete per-call graph/write history needed for certificate replay. Hash hits, event counts or local node ranks cannot substitute for that missing history.

## Full accounting

For a future candidate, compare complete work at the same semantic endpoints:

```text
baseline: initial validation + middle computation + final validation

candidate: initial validation with tracking
         + middle computation with complete delta capture
         + invalidation closure
         + ordered replay and new computations
         + certificate/log maintenance and retained storage
```

All first construction, delta generation (including any whole old/new scan), dependency indexing, obsolete-edge removal, invalidation, replay and output combination must be charged. Existing within-validation kind memoization is part of the baseline, not a new benefit.

Track current facts/edges and their lifetimes as well as cumulative work. A real memory claim additionally requires bytes/retention evidence with the old graph, result and certificate kept alive for the claimed period; logical edge counts alone do not establish heap or peak residency. GC, shared thunks and observer overhead must not be hidden.

A shadow deliberately performs the complete final validator too. Its wall time is not the optimized program's wall time. Lazy stage intervals can overlap and include shared evaluation or GC; they cannot be subtracted mechanically into exclusive savings.

## One bounded real gate, only after separate admission

If the source and finite gates establish the missing production obligations, the first real shadow should use the already-qualified Root + Foundation `--type` input paths and exact original stdout/stderr/exit gate. Preserve the previous raw/error qualifications and all samples. No synthetic scale-up, additional profile, repeated Foundation window or expanded resource cap follows from the model result.

Stop on any false-clean fact, changed first error or poison demand, incomplete/unbounded invalidation, or an unsupported identity transfer. Stop the optimization direction if delta/invalidation/replay covers nearly the whole graph without a clear net reduction after first construction and retention are included. A hit rate, a smaller warm-only counter or the historical combined validation profile envelope is not sufficient.

Only a separately reviewed, material net mechanism could justify a different real workload such as Async `--type`. It would need its own qualification, not inherited performance or compile-crate evidence. No such shadow, workload or production experiment is authorized by this archive.
