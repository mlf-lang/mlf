# Interpretation and limits

## Two separate diagnostics
Source v3 screened repeated complete encoded local problems. Source v4 added a reported elapsed interval around the original action until its Either constructor reached weak-head normal form (WHNF). They are distinct runs and producer binaries, not an A/B performance comparison. No values are pooled and no cross-run speedup is calculated.

## What is encoded
The grammar covers physical IntMap Nil/Tip/Bin shape, cached counts/prefixes and ordered children; all logical node fields, binders, flags, alias links, nextId and ordered equations with duplicates. Strings are encoded by character values, not internal Text representation or heap identity. The two Word64 fingerprints are noncryptographic screening keys. A matching key is not proof of equal graphs, successful reuse, alpha-equivalence or legal cache behavior. Raw real graphs/equations were not retained, so the real fingerprints cannot be recomputed from this aggregate archive.

The finite fixture contains 26 exact synthetic token streams plus Left bypass, Right demand and bounded-input checks. The two accepted rows use synthetic actions, not a real Solver workload. It does not cover every global-cap edge, exception or liveness case. Original source-only v1/v2 defects remain in private history; they are not successful executions.

## Demand and timing
The wrapper evaluates the original action once syntactically to Either WHNF, then fully encodes its input only for Right. It preserves the original returned value but changes demand, allocation, residency and timing. It is not a semantics-preserving general production replacement. Left records a zero fingerprint without forcing the input or error payload. A thrown action, encoding exception or rejected cap produces no accepted row; no missing row is synthesized.

action_whnf_ns does not force the result Graph. Demanding input/equation thunks may re-enter another observer, so accepted-row order is not proof of invocation order, exclusive time or non-overlap. Reported interval sums can exceed external wall time. They may include shared-thunk demand, GC and scheduling, and are not Solver CPU, allocation, complete result cost or a disjoint validation/rebinding phase partition.

encoding_ns records the fingerprint computation/forcing interval. In-interval GC or scheduling may be included. It is not total observer overhead and cannot be subtracted from diagnostic wall time to infer an ordinary runtime.

## Bounds and statistics
Both real diagnostics use one fixed Root/Foundation --type input closure, require exit zero, Bool plus LF and empty stderr, and retain external compile/target/whole caps. Those step durations are budget telemetry, not performance samples. The runs do not execute the user's compiled application or MLF native-backend/fixed-point qualification.

Successful input node bins are 0–16, 17–64, 65–128, 129–512, 513–2048, 2049–8192, 8193–32768 and 32769–131072. Counts, reported sums, exact medians and top-ten intervals are descriptive. Left rows have unobserved input size, not a measured zero-node graph. There is no benefit threshold, and an outlier alone does not select an optimization. Earlier profiling SCC entries are not interchangeable with these events or node counts.

The full-graph cache direction remains NO_GO. No production adoption, stable-performance result, generalized semantic guarantee or automatic follow-up is claimed. Main and the user's PR are unchanged; native work remains paused.
