# Haskell standard-core cutover: reviewed-source checkpoint

This records the implemented v3 semantic boundary at a local reviewed-source checkpoint. It is not a completed native bootstrap or release claim. The prior additive checkpoint, 2916c477, remains a separate historical snapshot.

## Source identities

Both source profiles fix `[]`, `(:)`, tuples, and `()` to standard builtin identities, independently of imports, hiding, qualified custom constructors, or local declarations named List, Nil, Cons, Pair, or Unit. An explicit custom datatype remains nominally distinct. The compiler's shared source and guest consumers were migrated once by identity-resolved AST spans; the ordinary GHC build does not translate source, use CPP, or use RebindableSyntax.

Boxed tuple constructors/types support arities 2–64, including prefix and partial applications. Arity 65 is rejected; 64 is the pinned GHC 9.14.1 boundary. The selected native instances include Eq for existing scalar types, Char, unit, lists and tuples 2–15; Functor/Applicative/Monad/MonadFail for lists; and tuple Functor 2–7. These ranges follow pinned base for those instance families. This is not a claim to implement every base class or instance.

Public IO/ST unit results are now canonical (). ABI constructor tag 0 is a private legacy tombstone, not a public Unit alias. Canonical () has tag 1; canonical list tags are 2/3; tuple 2–4 tags 4–6; stack frame/evidence tags 7/8; tuple 5–64 tags 9–68; user tags begin at 69. Only the v3 runtime guard is exported; stale pre-v3 objects fail closed rather than link against an incompatible unit/tag contract. The primitive ABI is `mlf-primitive-107-v4`; interface/query schemas are v4, and the current builtin interface/crate identity is v8. Stale builtin-v7 dependencies are rejected, including the dependency-selection shortcut.

## Strings, equality, and character boundary

Source string expressions and patterns in both profiles use genuine IsString with a canonical [Char] input. Patterns additionally use canonical Eq, independent of a local ordinary `(==)` function. Ordinary `(==)` and `(/=)` expressions remain lexically shadowable. Different literal spellings may overlap under lawful instances: pattern rows retain source order and retry later rows after subsequent-column failure.

Char supports every code point 0 through 0x10ffff, including surrogates. Escaped source literals preserve those code points without forcing an opaque-text intermediate. Scalar literals retain a scalar fast path. The explicit opaque-text adapter can reject surrogates when demanded; that restriction is not imposed on [Char] or a custom IsString instance. Raw printable-character acceptance follows a generated, exhaustively checked table for the pinned GHC. Source gaps currently support ASCII whitespace only; Unicode-space gaps are explicitly outside the selected grammar rather than imitating a pinned GHC panic. Internal primitive diagnostic strings and artifact/X text parsing remain separate from overloaded source literals.

## Do and demand

Both profiles use canonical `>>=`, `>>`, and MonadFail, not a locally shadowed bind/fail or an unrelated class named Monad. Refutability uses the complete resolved constructor family, including hidden constructors. A non-failing tuple or sole-constructor pattern need not be non-strict. Lazy and as-patterns preserve nested lazy boundaries, type obligations, sharing, and unused-match non-demand.

The lazy-match elaboration retains generalizing lets plus an undemanded witness for class obligations. A rejected intermediate lambda-only implementation was not retained: it lost rank-polymorphic payload behavior. Independent old/new controls preserve rank-N fields, richer MLF polymorphic tuples, and inferred target schemes. No core inference solver or target exhaustiveness check was weakened.

Managed HasCallStack is compiler-provided evidence, not an ordinary nullary class. Unsigned functions do not infer it; explicitly qualified signatures forward it. Module/package/file/source positions survive separate compilation. Typed IO failure is deferred and catchable, distinct from pure panic. Scoped exception-handler context and async cleanup are retained. Native diagnostics preserve source-origin behavior, not byte-for-byte GHC implementation-internal stack frames. Unrelated legacy HostError operations are not silently recategorized as catchable IOException. Copied top-level helper definitions retain their original managed lexical scope: an unsigned top-level helper does not capture an enclosing instance method’s call stack. An internal source-definition provenance node is erased during class elaboration; explicitly qualified helpers install their own given, while genuine method-local lets retain their lexical capture.

## Legacy syntax compatibility

Legacy annotations and MLF polymorphism remain supported, but single-colon syntax no longer steals a complete canonical cons expression or pattern. `(x:xs)`, `(x:Nil)`, and `x:Int` are cons when they form a complete expression/pattern, irrespective of capitalization. Write `::` for an ambiguous intended value or pattern annotation. Single-colon annotation fallback remains for syntax that cannot form a complete expression/pattern, such as forall/arrow types. Declaration signatures remain `:` or `::` as supported before. Active intended annotations were migrated by authenticated old-AST spans; genuine cons examples were not rewritten.

Unchanged legacy numeric and Boolean forms retain their previous AST/type/erasure behavior. This work does not add Num defaulting, change Int/arithmetic/ordering, or add a recursion solver. Do-let recursion follows the existing recursive-binding mechanism; the original same-name shadow examples remain explicit signature-requirement tests, not discarded coverage.

### Typeclass expansion strategy repair (2026-10-24, integration checkpoint)

This section supersedes the earlier *current* status wording without replacing its historical receipts. The user-authorized repair concerns the compiler's typeclass constraint expansion strategy, not a complete implementation of qualified MLF. Its paper basis is [Leijen and Löh, *Qualified Types for MLF*, §6/Figure 11](https://www.microsoft.com/en-us/research/wp-content/uploads/2016/02/qmlf.pdf): simplification must carry evidence reconstruction together with the changed type. Class-name-only deduplication and changing a scheme without rebuilding its applications are not valid substitutes.

The crate source-SCC route now keeps source bodies unexpanded until their predecessors have final checked contracts. For a provenance-authenticated, nonrecursive, unsigned source binding, it may discharge the entire generated outer ordinary evidence prefix when all domains are supported ground types and the definition's exact visible instances supply checked proofs. It applies the untouched old RHS to those proofs, checks the resulting term/type and parameterized object, and only then exposes the compact contract to later source groups. Explicit, recursive, copied-helper, managed and unsupported boundaries retain their existing contracts. If any slot cannot be simplified, the production policy retains the entire original binding; it does not perform partial residual contraction. No-discharge paths preserve the original term rather than adding eta wrappers.

This is optional simplification. Missing, cyclic or overlapping proof search preserves a valid residual contract; malformed provenance, invalid types and invalid evidence remain errors. The ordinary public evidence resolver retains its prior rejection behavior when a program actually demands unavailable evidence. Managed protection follows original declarations, imported metadata, actual free predecessor uses in the checked raw implementation and selected proof prerequisites; merely having an unrelated protected instance in scope does not disable an ordinary binding. Managed call-stack evidence is never ordinary ground evidence for this transformation.

The raw inference result remains the query-cache payload, retains existing checked-object/context validation, and additionally checks the exact source-issued evidence prefix after type erasure. Both cache misses and hits finalize the checked boundary before publishing a successor ABI. A separate source-query namespace includes definition scope, exact slot provenance, predecessor contracts and proof-candidate types. Final objects include proof-only parameters and their transitive datatype layouts. MLFCI-5 and the crate semantic epoch distinguish the new strategy; complete binding protection metadata survives dependencies, reexports and release relocation. Old metadata is rejected rather than silently relabelled. The runtime Value ABI is unchanged.

Focused production-route tests have passed actual source-SCC inference, cold/warm raw-cache behavior, exact final object parity, protected and ordinary proof selection, metadata-only provider/facade/consumer compilation with the provider source unavailable, decoded-object linking and evaluation, and release relocation/roundtrip controls. The full 106-module GHC exhaustiveness audit and live evidence regression suite also passed at their recorded snapshots. The fresh 106-module GHC producer and six genuine lock/plan roots have passed; original unsigned compiler-trigger bindings, complete modular self-compilation and native A/B fixed point are still required gates, not implied by these focused results. The earlier signature mitigations and OOM diagnostics remain evidence, not a general solver repair claim.

MLF graph solving, per-expression generalization, bounded-variable ownership and defaulting policy are unchanged. Nested impredicative field qualification and general residual-predicate normalization remain outside this phase. In particular, the earlier discarded-field/string example is a limitation of the current qualification placement, not a permanent theoretical rejection oracle for qualified MLF.
