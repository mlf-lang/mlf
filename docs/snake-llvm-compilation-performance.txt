Scope and method
----------------
The three eMLF measurements all begin with examples/snake.emlf and use the
standard prelude. They are complete workflows, not additive stage timings:

  xMLF: emlf examples/snake.emlf, capturing verified xMLF on stdout.
  LLVM IR: emlf --emit-llvm examples/snake.emlf, capturing LLVM IR on stdout.
  LLVM native: a fresh --emit-llvm invocation, writing its IR to disk, then
    clang -O2 snake.ll runtime/mlf_runtime.c $(pkg-config --cflags --libs gmp)
    -o snake-llvm, including optimization, runtime compilation, and linking.
  GHC native: ghc -O2 -Wall -Werror -fforce-recomp -main-is SnakeBaseline
    examples/SnakeBaseline.hs -outputdir <scratch> -o snake-haskell.

Both native workflows produce linked executables. The LLVM native workflow
recompiles the C runtime in every sample; no cached runtime object is used.
GMP and the GHC libraries are already installed. The IR-only workflows stop
before native code generation and linking. The similar xMLF and LLVM IR
medians do not establish a meaningful speed difference at this sample size.

Runs are serial, and workflow order rotates by one position each round:
  1: xMLF, LLVM IR, LLVM native, GHC
  2: LLVM IR, LLVM native, GHC, xMLF
  3: LLVM native, GHC, xMLF, LLVM IR
  4: GHC, xMLF, LLVM IR, LLVM native
  5: xMLF, LLVM IR, LLVM native, GHC

Every compilation uses fresh processes. Timing includes startup, reading
source, inference, elaboration, target verification, and the selected output
pipeline. No successful game compilation or emitted IR is reused by a timed
workflow. Compiler builds, metadata probes, output validation, and game
execution are outside the measured regions. No source-compilation warmup
is performed; these are not cold filesystem-cache measurements.

The tools are queried for metadata before timing. Probe durations were
0.060596 s for GHC, 1.405387 s for emlf RTS information, 0.171138 s for Clang,
0.004728 s for GMP version, 0.003597 s for GMP flags, and 0.018188 s for the
runtime path. These results therefore exclude first-launch initialization.

Reproduction
------------
cabal bench -j1

Cabal builds the emlf tool dependency before launching compiler-bench. The
runner invokes the same process-based timing driver used for the recorded
samples above. Build time and benchmark startup are outside the measured
regions. The default is five rounds, with the report and .xmlf/.ll artifacts
written to dist-newstyle/benchmarks/snake.*.

To choose options or a report location:
cabal bench compiler-bench -j1 \
  --benchmark-options='--runs 5 --output dist-newstyle/benchmarks/llvm-comparison.json'

Requires Python 3 (standard library), Clang, pkg-config, and GMP development
files. Pass --clang and --pkg-config through --benchmark-options to select
alternate tool paths. Optionally include --reference-xmlf /path/to/saved.xmlf
to require the earlier xMLF output; the recorded run used
dist-newstyle/compiler-parity/final-ghc-comparison.xmlf.

The script prints the table and writes raw timings, ratios, commands,
metadata, and hashes to JSON. It saves .xmlf and .ll beside the JSON. The
legacy emlf/ghc fields and --max-ratio gate continue to refer to xMLF/GHC;
new llvm_ir/llvm_native fields expose the additional workflows separately.
Validation failures and missing tools fail the benchmark.

The optional revision comparison uses the same Cabal entry point:
cabal bench compiler-bench -j1 \
  --benchmark-options='compare-revisions --before /path/to/saved-emlf'
It compares all examples by default and saves
dist-newstyle/benchmarks/revisions.json. Explicit source paths select a subset.
