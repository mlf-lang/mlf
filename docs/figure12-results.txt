Reproduce
---------
./mlfpkg --timeout 21600 test --target unit
./mlfpkg --timeout 21600 test

The paper acceptance oracle is the MLF column, not the Quick Look column.
tests/Tests/Figure12.emlf contains all 34 rows and 43 semicolon-separated expressions.
It stores paperAcceptance separately from expectedAcceptance for the regression.
tests/Figure12SuiteMain.emlf checks coverage and both sets of expectations. The paper's
four rejections are A11, C1a, C1c, and E1a. The regression additionally requires
A8 to reject under its explicit signature, matching the authors' camlf reference
prototype; see docs/figure12-a8-reference.txt. The suite prints this discrepancy
and does not count A8's rejection as agreement with the paper.

Encoding
--------
The Figure 12 harness uses the closed-term API. Each open expression is
closed with one annotated lambda parameter per free library name, using its
signature in Figure 1 or the local signature in Figure 12. The parameter
annotations desugar to coercions and polymorphic let bindings. No annotation
is added to the original expression's local lambda binders or applications.
Each assumed signature is also tested in isolation, including target checking.

The syntax-only adaptations are:
  [t] -> List t; (t,u) -> Pair t u; (e,f) -> pair e f;
  [] -> nil; (:) -> cons; the paper's list concatenation (+) -> append;
  lambda/dot -> backslash/arrow; (::) -> (:).
The ordinary pair constructor has type forall a b. a -> b -> Pair a b.
length has its ordinary type forall a. List a -> Int.
The implicit b in auto' is explicitly universally quantified at the outside:
  forall b. (forall a. a -> a) -> b -> b
In particular, this is not replaced by auto's differently scoped type.
A1 tests the right-hand side of the displayed const2 definition.
A11 closes the missing parenthesis in the printed expression.
The two k signatures (A11 and section E) are kept distinct.
No definitions of library functions are inferred in place of their signatures.
Repeated expressions across rows retain their separate labels.

What a passing case checks
-------------------------
For acceptance, source parsing, graph inference, elaboration, and the compiler's
type and erasure verification must all succeed. The emitted xMLF is then pretty
printed, parsed again, and checked with the independent target checker. Its type
must be alpha-equivalent to the compilation result and its erasure unchanged.

For rejection, failure must be in inference, with the expected diagnostic:
an Int/Bool constructor conflict for A11/C1a/C1c, and protected-variable raising
for A8/E1a. Missing assumptions, parsing failures, exceptions, and failures in
elaboration or target checking do not count as expected rejection.
A11/C1a/C1c additionally have accepting controls with the explicit polymorphic
parameter annotation that MLF requires; E1b is the accepting control for E1a.

Observed result
---------------
All 43 expression outcomes match the regression expectations: 38 acceptances
produce checked xMLF and five rejections have the required inference diagnostics.
42 of 43 outcomes agree with the MLF column (33 of 34 complete rows). A8 is the
only difference:

  choose id auto'
  paper:      accept
  regression: reject
  actual:     Inference: cannot raise a protected type variable

A closed reproduction using annotated library parameters with the exact
Figure 1 signatures is preserved in tests/fixtures/figure12-a8.emlf:

  .mlf-build/bin/emlf --type tests/fixtures/figure12-a8.emlf

The original check also used ordinary closed lambda implementations at those
signatures; both forms produced the same inference rejection.

The implementation of auto' alone compiles at its declared type. Thus the A8
failure is reproducible without the harness's assumed-library lambda wrappers.
The failure is in the inference permission check, before xMLF elaboration.
The authors' reference prototype rejects the same explicit signature for the
same binder-raising reason. Both accept controls with an inferred, more general
MLF type or result-local quantification; those are different types and do not
replace the A8 signature. Rejection is now the regression expectation for this
encoding. The correspondence with the paper remains unresolved; this is not a
proof that the paper is wrong. The production compiler was not changed.

The original 2026-10-06 validation used GHC 9.14.1 and Cabal 3.18.1.0.
Those harnesses are retired; current reproduction uses the native MLF commands
above. The historical totals below describe that original validation.
The 36 supplementary checks pass (29 assumptions, 4 type checks, 3 annotated
negative-case controls). The original mlf-tests suite passes all 76 checks,
including 6,712 comparisons with the independent ML oracle and the 126-program
annotation corpus. The combined cabal test command succeeds. A8 is an active
negative test requiring its specific inference diagnostic, with the paper's
acceptance recorded separately.

Types mentioned by the figure
-----------------------------
A1's inferred type is checked up to alpha-equivalence against:
  forall a. forall (b >= forall c. c -> c). a -> b
A2's inferred type is checked up to alpha-equivalence against:
  forall (a >= forall b. b -> b). a -> a
For A2 the closed test implementations have the same declared signatures.

A4's printed target type is not literally the System F type shown in the
figure. The compiler retains a flexible result bound:
  forall (b >= forall a. a -> a). (forall a. a -> a) -> b
An additional compilation verifies that the same expression admits the paper's
signature as an explicit source annotation:
  (forall a. a -> a) -> (forall a. a -> a)
These are separate checks, not an assertion of xMLF alpha-equivalence between
the two representations or a general proof of principality.

Scope
-----
These Figure 12 tests assess static typing and compilation evidence. List,
Pair, ST, and Char are uninterpreted type constructors in this encoding;
execution is covered separately by the native backend and port groups.
Agreement on this finite table would not prove completeness of the thesis's
inference or translation algorithms. A8's explicit-signature regression passes
on rejection, so a green suite still does not establish full table agreement.
