Scope and method
----------------
eMLF compiles examples/snake.emlf with the standard prelude to verified,
captured xMLF. GHC compiles examples/SnakeBaseline.hs to a linked native
executable with -O2 -Wall -Werror -fforce-recomp -main-is SnakeBaseline.
These are different output formats. This measures the requested compilation
workflows, not equivalent native backends or game execution.

Each sample starts a fresh process. GHC recompiles and links every time;
neither compiler reuses a successful game compilation. Order alternates
eMLF/GHC, GHC/eMLF. Timing includes ordinary process startup, source reading,
parsing, inference, elaboration, verification, and captured output. It excludes
building emlf and running either game. The gate checks every pair, not only
the median. The default --max-ratio is now 1.

Both compiler executables are queried for metadata before the measured runs:
GHC --numeric-version, and emlf +RTS --info -RTS. Neither probe compiles a
source file. The previous script already queried GHC; it now treats emlf
similarly and records both probe durations. In this run immediately after
linking emlf, the probes took 0.057779 seconds for GHC and 0.705305 for emlf.

The target therefore covers compilation after executable initialization.
It does not establish that the first invocation of a newly linked emlf
binary is faster than GHC. An earlier component-solver build's first launch
took 0.959051 seconds against GHC's 0.830517 seconds (1.1548x), followed by
0.215572 and 0.216571 seconds. Similar one-off overhead appeared on a trivial
source. OS executable initialization is a plausible explanation; its exact
cause was not established. This cost is disclosed rather than counted as
an improvement to source compilation.

Implementation
--------------
The earlier unifier visited the whole accumulated graph for every instance
edge. Profiling identified repeated graph validation, rebinding, resolution,
and associated allocation as the remaining bottleneck.

MLF.Graph.Solver now maintains structural-parent and binding-child indexes.
Starting from an equation's endpoints, it closes over structural edges in
both directions and type binding edges in both directions. Generalization
nodes stop the type traversal, while their full binding ancestry is retained.
This includes incoming references, shared types, and protected siblings.

The selected component is projected to compact scratch identities, preserving
the ascending original order and therefore union representative choices.
Unrelated generalization roots use private bottom placeholders. The existing
MLF.Graph.unify runs unchanged, including validation before and after the
merge, Rebind, occurs/kind checks, and original-identity permission checks.
The solver verifies placeholders and generalization scopes stay unchanged,
restores original identities and roots, and updates only affected indexes.
Placeholder identities cannot escape into the resulting graph.

This boundary preserves the information used by the unifier: type permission
paths stop at generalization nodes; inertness depends on binding descendants;
and the complete structural parents and binding ancestry retain relevant
scope constraints and lowest common ancestors. Generalization nodes cannot
be merged or be structural children, and their binding parents remain fixed.

The solver constructor and record selectors are private. Its exported graph
accessor is an ordinary function, so clients cannot replace a graph without
maintaining its indexes. A full graph validation initializes the solver;
finish independently reconstructs both indexes and validates the complete
inference result. Normalization is followed by another full graph validation.

Elaboration reuses the final presolution's indexes. Each non-reflexive edge
still expands from that final graph, solves its frontier separately, and
returns the original-to-copy identity map for evidence construction. Checked
Inst-Refl remains available for alpha-equivalent types. Independent target
typing, computation checking, inferred-type agreement, and source erasure
checks remain enabled. No Snake-specific path or compilation cache was added.

Reproduction
------------
cabal bench compiler-bench -j1 \
  --benchmark-options='--runs 5 --output dist-newstyle/benchmarks/ghc-comparison.json'

The current Cabal entry point also measures the LLVM workflows. Optionally
add --reference-xmlf /path/to/snake-before.xmlf to --benchmark-options to require
equality with a saved earlier output. The driver uses Python's standard
library and records raw timings, metadata probe durations, commands, and
fingerprints.
It saves checked xMLF beside the JSON report and fails if any pair exceeds 1.
Timings depend on the machine and its load.
